Claude Code + Emacs Integration

My setup for running Claude Code inside Emacs, so that Claude can both run in a terminal buffer and control Emacs itself (open files, launch shells, create frames, etc.).

Download zip

What's included

  • ec — A wrapper script that gives Claude a reliable path to emacsclient. On macOS, the binary bundled inside Emacs.app isn't on the default PATH.
  • init-excerpt.el — The relevant sections of my Emacs config: server start, vterm setup, Claude Code launch commands, auto-revert, and exec-path-from-shell.
  • CLAUDE.md — The instructions that teach Claude how to interact with Emacs: opening files, jumping to lines, launching terminals, cleaning up buffers, etc.
  • README.md — Full setup instructions.

Quick setup

  1. Install Claude Code and vterm for Emacs.
  2. Copy the relevant pieces from init-excerpt.el into your Emacs config.
  3. Place ec on your PATH (e.g., ~/.local/bin/ec) and make it executable.
  4. Add the contents of CLAUDE.md to your Claude Code configuration.
  5. Open Emacs, then C-c c c to launch Claude Code in a vterm buffer.

How it works

Claude Code runs inside vterm, which is itself an Emacs buffer. Claude then uses emacsclient to reach back into Emacs. This two-way communication is what makes the integration feel seamless.

Update: MCP server (faster approach)

The emacsclient approach above works well, but every call spawns a new process (~24ms overhead). I've since built an MCP server that replaces emacsclient with a persistent TCP connection. The result is ~25-30x faster and bidirectional: Claude can also read from Emacs (buffer contents, selections, buffer list), not just write to it.

The MCP server provides seven tools: evaluating elisp, opening files, reading buffer contents, listing buffers, getting selections, saving buffers, and inserting text into the scratch buffer. See the GitHub repo for setup instructions.
